Wind Forecasting & Alignment — README

Two related Python pipelines are included:
1) wind_pipeline.py — hybrid ARIMA (SARIMAX) + LSTM residual pipeline (modular, per-pin ARIMA + global LSTM on residuals). 

wind_pipeline


2) wind_pipeline_lstm.py — single-file LSTM-first pipeline (LSTM predicts u/v directly; includes full CLI + visualization). 

wind_pipeline_lstm

Both projects share the same goal: fetch historical weather for a grid of pins (Open-Meteo), build models to predict short-term wind speed & direction, and produce simple visualizations (folium maps, plots). The repo also includes two supporting guides used to design the pipeline: a short LSTM primer and a SARIMAX reference.

Quick summary (what each script does)
wind_pipeline.py (Hybrid ARIMA + LSTM)

Builds a ring-style grid of pins around a center point and saves a folium map.

Downloads hourly historical weather (windspeed, wind direction, temp, pressure, humidity) for each pin from Open-Meteo and stores a combined CSV.

Converts wind direction → vector components u, v.

Trains per-pin SARIMAX models on u and v (captures linear/seasonal baseline), stores models (pickled).

Computes residuals (res_u, res_v) = observed − ARIMA_pred.

Trains a single (global) LSTM that predicts residuals from a lookback window (so final prediction = ARIMA_forecast + LSTM_residual).

Forecast + visualization utilities (map, line plots). 

wind_pipeline

wind_pipeline_lstm.py (LSTM-only starter)

Everything in one file: grid generation, data fetch, compute u/v, LSTM training that predicts next-step u,v directly, and prediction/visualization CLI.

Good as a quick prototype and demonstration; simpler than hybrid pipeline. 

wind_pipeline_lstm

Why hybrid (ARIMA + LSTM)?

ARIMA (SARIMAX) captures linear + seasonal patterns reliably, especially for short-term periodic components. LSTM captures nonlinear residuals (gusts, turbulence). Combining them often reduces RMSE and gives smoother short-term control for turbine yaw/pitch. The repository implements ARIMA per-pin on u/v and trains LSTM on residuals.

Important function notes & default behavior

Grid generation: generate_grid_map(center_lat, center_lon, outer_radius_km, outer_points_per_ring) — creates inner and outer rings around center, returns (folium_map, grid_df, pin_list) where pin_list is [(lat, lon, label), ...]. 

wind_pipeline

Data fetch: fetch_weather_for_pins(pin_list, start_date, end_date, out_csv, variables, timezone) — by default fetches high-altitude variables (100m winds) and common met variables; caches CSV if present unless overwrite=True. API endpoint: https://archive-api.open-meteo.com/v1/archive. Respect polite pauses (script uses time.sleep(0.2) between pins). 

wind_pipeline

u/v decomposition: Both scripts compute u = speed * cos(theta) and v = speed * sin(theta) and add cardinal flags is_N/is_E/is_S/is_W (45° wedges) to help models with directionality. This avoids circularity in angles.

ARIMA (SARIMAX): train_arima_models(...) fits SARIMAX to u and v per pin, saves pickled results, returns augmented dataframe containing arima_u_pred, arima_v_pred, res_u, res_v. Default ARIMA orders used in the scripts are sensible starters, e.g. order=(2,0,2) and seasonal_order=(1,1,1,24) for hourly seasonality. Each pin needs enough history (script enforces minimum ~48 rows) to fit seasonal models. 

wind_pipeline

LSTM training:

Hybrid: trained on residuals (res_u, res_v) with features including ARIMA predictions, base met vars, hour/day-of-year flags, and cardinal flags. This helps the LSTM learn nonlinear residual structure efficiently. 

cdc8f679-8fbf-4983-96cc-f9d3262…

LSTM-only: trained directly on u,v features, typical architecture: LSTM(128) → Dropout → Dense(64) → Dense(2), compiled with mse loss. EarlyStopping + ModelCheckpoint callbacks used. Defaults: lookback 24 hours, epochs 20–50, batch_size 64.

Prediction & recomposition:

Hybrid: forecast ARIMA baseline for forecast horizon, LSTM predicts residuals → final = ARIMA + residual. Works per u/v, then recomposed to speed & direction via speed = sqrt(u^2 + v^2) and direction = atan2(v, u).

Tips, caveats & suggestions (practical)

Data quantity & seasonality — SARIMAX needs enough history to learn seasonal cycles; for hourly data a seasonal period of 24 is common, but validate with ACF/PACF and domain knowledge. Avoid over/under differencing. 

33be1998-7a6b-408e-9210-54a67e4…

Direction handling — always convert angles to u/v components for modeling; this avoids wrap-around issues at 0°/360°. 

cdc8f679-8fbf-4983-96cc-f9d3262…

Per-pin vs global models — the hybrid script trains SARIMAX per-pin (good) and a single global LSTM on residuals (simple). For production, consider:

training separate LSTMs per-pin (if data & compute permit)

using pin embeddings or station identifiers as categorical inputs

hyperparameter search (optuna / Keras Tuner)

ensembling multiple LSTMs for uncertainty estimation. 

wind_pipeline

Model format — Keras will warn about HDF5 being legacy; consider saving as .keras especially for future compatibility. 

cdc8f679-8fbf-4983-96cc-f9d3262…

API & rate limits — Open-Meteo archive is used for historical hourly data. The scripts include a short pause between pin requests; if you scale up the grid, respect API policies and add exponential backoff / caching. 

wind_pipeline

Units — internal units are m/s; final outputs convert to km/h for plotting/display. Be consistent across preprocessing, models, and downstream control logic.
